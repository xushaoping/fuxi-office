## 一、项目背景

企业的贷款审批、订单优惠、航班延误处置、风控分级等业务，通常依赖制度文件、Excel 规则表和人工经验。传统规则落地存在四类问题：

• **认知门槛高**：业务人员需要同时理解自然语言、技术 DSL、DMN XML 和 FEEL 表达式
• **沟通成本高**：规则从需求到上线跨越建模、开发、测试、审批多个环节
• **维护风险大**：变更容易引起引用丢失、边界遗漏、版本不可追溯和线上结果难解释
• **LLM 直接决策不可控**：直接让大模型回答业务结果，存在随机性、幻觉、不可审计和难以回放的问题

### 伏羲的解决思路

使用**多智能体协作**理解和生成结构化决策模型，再由确定性的 DMN/FEEL 引擎进行校验、执行和审计。AI 提升建模效率，规则引擎保证生产可靠性。

---

## 二、项目定位与目标（v1.0.0 升级）

伏羲是一个全栈 Rust 实现的企业级 DMN 决策自动化平台，**智能化成熟度已达 L3（半自动闭环）**。平台将"自然语言需求"转换成"可验证、可版本化、可发布、可观测的决策服务"。

### 核心能力

• **多智能体协作编排**：Analyst、Architect、Engineer、Tester 等多角色并行工作，支持心跳监控、失联恢复、取消传播
• **RAG 知识增强**：知识分块（约 400 token）、向量索引、混合检索（关键词+向量+RRF），自动注入相关上下文
• **阶段化人在回路**：需求分析 → 澄清确认 → 方案规划 → 模型生成，每步可控可验证
• **结构化中间层**：以 DSL 作为中间表示，统一连接 Agent、编译器和运行时
• **多层确定性校验**：DSL → DMN 编译 → FEEL 语法 → 依赖完整性 → 契约测试 → 历史回归
• **完整运营闭环**：决策解释、偏差归因、漂移检测、优化建议、Shadow 评估、效果追踪
• **全链路可追溯**：从 Agent 输入、DSL、DMN 制品、测试、审批到运行轨迹和业务反馈

## 三、总体技术架构（v1.0.0 升级）

### 分层架构

**交互层**
- Leptos CSR / WebAssembly 工作台
- 自然语言输入 · 模型与验收可视化
- 运营 Copilot（自然语言查询指标）

**服务层**
- Axum API · JWT 认证 · 项目级 RBAC
- SSE 流式反馈 · 决策服务端点
- 批量业务结果回传

**智能层**（⭐ v1.0.0 重大升级）
- **多智能体协作编排**：并行执行、心跳监控、失联恢复
- **RAG 语义检索**：向量索引 + 关键词 + RRF 融合
- **阶段化工作流**：需求分析 → 澄清 → 规划 → DSL 生成 → 增量修改
- **Tester Agent**：自动生成测试提案 + LLM-as-Judge 复核

**编译层**
- Decision DSL → 结构校验
- DMN 1.5 XML 生成
- FEEL 预编译与依赖分析

**运行层**（⭐ v1.0.0 新增）
- 确定性 DMN/FEEL 执行 · 规则命中 · 执行轨迹
- **决策解释生成**（按需自然语言解释）
- **偏差归因**（智能归因候选 + 人工复核）
- **漂移检测**（每日扫描 + 事件驱动）
- **优化闭环**（建议 → 模拟 → Shadow → 效果追踪）

**数据层**（⭐ v1.0.0 优化）
- PostgreSQL 14+ / pgvector
- **按月分区存储**（决策运行）
- **日粒度物化视图**（统计加速）
- **三角色权限隔离**（postgres / fuxi_owner / fuxi）

## 四、核心功能与应用场景（v1.0.0 升级）

### 智能建模能力

**多智能体协作编排**
- Analyst、Architect、Engineer、Tester 并行工作
- 心跳监控、失联恢复、取消传播
- 编排历史查看与任务取消

**RAG 知识增强**
- 知识分块（约 400 token）、向量索引
- 混合检索（关键词 + 向量 + RRF）
- Top-5 命中率、MRR、nDCG 评测

**阶段化工作流**
- 需求分析：生成业务摘要、关键规则、输入输出、风险和澄清问题
- 澄清确认：业务人员回答澄清问题
- 方案规划：生成决策清单、依赖关系、命中策略
- 模型生成：DSL → DMN 1.5 XML，语法高亮与结构树可视化

**增量修改**
- 基于原始需求和当前 DSL 生成增量补丁
- 保护未变更元素，显式识别影响范围
- 支持结构化重试与错误自动修复

### 质量保障能力

**多层校验门禁**
- DSL 结构校验 → DMN 编译 → FEEL 语法 → 依赖完整性 → 契约测试

**Tester Agent**（⭐ v1.0.0 新增）
- 基于需求条目/约束自动生成测试提案
- LLM-as-Judge 辅助复核
- 人工审阅与采信率评测

**历史回归门禁**（⭐ v1.0.0 新增）
- 有基线的版本发布前必须通过历史回归
- 全部用例通过才能发布

**静态分析**
- 规则冲突检测（UNIQUE/ANY）
- 不可达规则（FIRST）
- 覆盖缺口识别

### 生产运营能力（⭐ v1.0.0 重大升级）

**决策解释**
- 按需生成自然语言解释（绑定版本与运行记录）
- 支持盲审标注、可读性评估
- 多 Reviewer 多数票机制

**业务反馈闭环**
- 批量自动回传业务结果（≤100 条/批次）
- 智能偏差归因（规则级候选 + 置信度）
- 人工复核（正确/错误/不确定）
- 归因评测（Top-1 准确率、校准误差）

**漂移检测与事件驱动**
- 每日自动扫描失败率、偏差率、输入分布、规则命中率
- 事件驱动触发优化提案
- 窗口标注与阈值回放评测

**优化建议闭环**
- 基于分析自动生成结构化建议
- 历史样本模拟（影响面评估）
- Shadow 资格评估（低风险项目、限定发现类型、最低样本数）
- 自动创建草稿（试点）→ 效果追踪

**运营 Copilot**
- 自然语言查询项目指标（运行量、成功率、失败率、偏差率、耗时）
- 意图识别与澄清
- 结构化指标返回

**提示词版本管理**（⭐ v1.0.0 新增）
- 版本控制、Golden 评测、激活回滚
- 提示词审计历史
- 激活后必须重启应用实例

## 五、v1.0.0 核心创新点

### 01 · 多智能体协作编排（L2 → L3 升级）
不再是单一 Agent 线性流水线，而是多角色并行协作，支持心跳监控、失联恢复、取消传播。

### 02 · RAG 语义检索（知识增强升级）
从全文注入升级到分块 + 向量索引 + 混合检索（关键词 + 向量 + RRF），显著提升检索准确率。

### 03 · 决策解释生成（可解释性）
按需生成自然语言解释，支持版本绑定、盲审标注、可读性评估，提升业务信任度。

### 04 · 偏差归因闭环（反馈闭环）
批量回传业务结果 → 智能归因候选 → 人工复核 → 归因评测，形成完整反馈闭环。

### 05 · 漂移检测与事件驱动（自动化运维）
每日自动扫描失败率、偏差率、输入分布、规则命中率，事件驱动触发优化提案。

### 06 · 优化建议真实化（闭环完整化）
从占位实现升级到：生成建议 → 历史样本模拟 → Shadow 资格评估 → 自动创建草稿 → 效果追踪。

### 07 · 运营 Copilot（自然语言运维）
自然语言查询项目指标，意图识别与澄清，降低运维门槛。

### 08 · 提示词版本管理（资产化）
提示词版本控制、Golden 评测、激活回滚、审计历史，提升提示词质量与稳定性。

### 09 · 数据存储优化（性能与治理）
按月分区存储、日粒度物化视图、三角色权限隔离，提升查询性能与数据安全。

### 10 · 完整评测体系（质量保障）
RAG 检索、Agent 编排、偏差归因、漂移检测、决策解释、Tester 提案，全部提供独立评测工具与 Wilson 95% 置信区间。

---

这套架构的关键价值在于：**把 LLM 的不确定性限制在"候选生成"边界内，把生产系统最需要的可重复、可验证、可回滚和可解释交给确定性工程。同时通过多智能体协作、RAG 检索、完整闭环，实现从 L2（单点辅助）到 L3（半自动闭环）的智能化升级。**

## 七、开源项目价值

• **对业务人员**：用业务语言建模，减少学习 DMN、XML 和 FEEL 的成本；通过决策解释理解决策逻辑。

• **对研发团队**：结构化 DSL、编译器和测试门禁降低规则代码维护成本；多智能体协作提升建模效率。

• **对管理与合规**：版本、审批、审计、回滚和执行轨迹形成治理闭环；偏差归因与漂移检测提升运营质量。

• **对平台建设**：Rust 单体二进制易部署，领域模块清晰，便于后续拆分服务。

• **对 AI 应用研究**：提供"多智能体协作 + RAG 检索 + 确定性运行时 + 人在回路 + 完整闭环"的可落地样例。
