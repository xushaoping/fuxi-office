## 一、优先解决的问题

**1. 高优先级：切换项目会清空未确认内容**
- `src/components.rs:1604` 的项目切换逻辑直接清空需求、澄清答案和待确认变更，没有先检查是否需要保留。

**2. 高优先级：样式通过反复追加覆盖，存在布局互相影响**
- `public/style/main.css:6681` 标注了“最终布局规则”，后面仍有大量覆盖；整个文件目前约 **8978 行、34 个媒体查询块**。

- 建议先梳理最终生效规则，再按用途划分控件尺寸，停止在文件末尾继续追加“修正补丁”。

**3. 高优先级：小字号和浅色辅助文字影响阅读**
- 样式中有 **271 处低于 12px 的字号声明**，不代表都最终生效，但说明小字号使用较多。例如页签计数为 8px：`public/style/main.css:7506`。
- 按声明颜色计算，浅色主题的 `--text-faint` 在 `--surface` 上对比度约 **3.17:1**：`public/style/main.css:6348`。
- 建议正文提高至 14px，重要辅助信息不低于 12px，并提高辅助文字对比度；版本状态、错误信息、操作提示不要使用“极小字号 + 浅色”的组合。

**4. 高优先级：窄屏只是纵向堆叠，工作区会过长**
- 工作区高度依赖 `100dvh - 157px / 174px / 205px` 等固定减值，顶部换行后容易失配：`public/style/main.css:7616`、`public/style/main.css:8469`。
- 小于 1100px 时，对话区和检查区分别存在 620px、980px 的最小高度设置：`public/style/main.css:7675`、`public/style/main.css:6916`。
- 建议用应用外壳分配剩余高度；平板和手机改为“对话 / 模型”切换，而不是把两块长面板上下堆叠。

**5. 中优先级：流式生成会打断用户阅读**
- `src/components.rs:608` 在消息或流式文本更新时，无条件滚动到底部。
- 建议仅当用户原本接近底部时跟随输出；用户向上阅读后暂停跟随，显示“有新内容，回到底部”。生成完成后提供“查看变更”入口，不强行抢滚动位置。

**6. 中优先级：主题状态没有真正统一**
- 工作台单独初始化为浅色：`src/components.rs:275`；全局状态另有持久化主题实现：`src/state/app_state.rs:86`。
- 建议只保留一个主题状态源，把主题挂到应用根节点，让工作台、管理页、登录页和全局通知一致生效，刷新后保留选择。

**7. 中优先级：基础交互规范不完整**
- 主导航声明为 `tablist`，但缺少完整的键盘切换和面板关联：`src/components.rs:3060`。
- 登录表单只有占位文字，缺少明确标签和自动填充属性：`src/components/auth/login_page.rs:66`。
- 删除项目有确认，但删除验收案例直接执行：`src/components.rs:2303`。
- 建议统一导航语义、表单标注和危险操作确认，而不是逐页面自行实现。

## 二、布局优化方案

**推荐方向：保留现有工作台结构，减少顶部竞争，把内容空间还给主要任务。**

```text
品牌 / 工作台                         运行状态    用户菜单
项目切换 · 当前版本 · 保存状态                  项目设置
──────────────────────────────────────────────────
需求与方案 → 建模 → 验收 → 服务       分析 / 版本 / 协作 / 资源
──────────────────────────────────────────────────
建模对话                         模型工作区
任务进度（可折叠）                概览 / 决策表 / 依赖图 / 源码
历史消息                         当前内容
变更摘要                         属性或详情（按需展开）
─────────────────                ─────────────────
修改需求输入框                   核验结果 / 问题定位
发送 / 停止
```

- **顶部减负**：用户账号、退出、管理入口收进用户菜单；项目栏只保留项目、版本和保存状态。模型库、知识库统一从资源入口进入，避免重复入口。
- **主次分组**：突出“需求 → 建模 → 验收 → 发布服务”的主流程；分析、版本、协作、资源作为辅助功能组。禁用入口同时解释开启条件。
- **桌面双栏**：对话区初始宽度建议 360–420px，模型区占剩余空间；允许拖动分隔线和单独展开模型区。
- **平板单区聚焦**：对话和模型使用分段切换，保留上下文，不强制堆成长页面。
- **明确滚动归属**：桌面由各工作面板内部滚动；移动端以页面滚动为主，避免多层滚动区域竞争。

## 三、视觉美化方案

建议采用 **“中性浅灰底色 + 白色内容面板 + 深绿色操作强调”**，让绿色表达品牌和操作，而不是铺满整个界面。以下为建议起点，不是最终定稿。

| 项目 | 建议 |
|---|---|
| 色彩 | 页面底色 `#F5F7F8`，面板白色，主色沿用深绿 `#23705E` |
| 字体 | 页面标题 22–24px，区块标题 16–18px，正文 14px，辅助文字 12–13px |
| 间距 | 统一使用 4 / 8 / 12 / 16 / 24 / 32px，减少零散尺寸 |
| 圆角 | 输入框和按钮 6–8px，独立卡片 10–12px；工作台分栏不必全部卡片化 |
| 按钮 | 桌面常规高度 36–40px，触屏操作目标建议至少 44px |
| 状态 | 使用“文字 + 图标 + 轻背景”，不要只靠红绿颜色区分 |
| 图标 | 统一单色线性图标与尺寸，避免彩色头像、装饰插画、符号混用 |
| 动效 | 保留短暂的颜色和透明度过渡，减少工具按钮悬浮位移 |

另外有两项值得一起调整：

- **每个操作区只突出一个主按钮**，其他按钮使用次级或文字样式；危险操作与主要流程保持距离。
- **浅色主题下不要让所有数据展示都变成深色代码块**：概览、字段、决策表保持浅色，源码可独立选择深色，减少视觉割裂。

## 四、各页面的交互优化

**需求与方案**
- 首次进入展示简洁引导和三个示例；有项目数据后收起大段介绍。
- 流程步骤跟随真实状态变化，明确下一步动作。
- 没有项目时直接提供“选择项目 / 创建项目”，不要让用户输入完、提交后才发现前置条件不足。

**建模工作区**
- 将只读 DSL 基线默认折叠，避免它与右侧模型产物重复占空间。当前位置：`src/components.rs:4288`。
- 生成完成后突出“变更摘要 → 查看差异 → 确认保存”，技术日志默认收起。
- 输入框自适应高度，保留停止、失败重试和快捷键提示；快捷键处理补充输入法组合状态判断。

**验收页面**
- 顶部先展示通过、失败、待批准数量，再展示案例列表。
- 默认展示案例摘要，展开后再看输入、期望、实际结果；优先提供“只看失败”。
- 将批量操作放进统一工具栏，错误信息就近展示；删除案例采用轻量确认或有后端支持的撤销机制。

**项目管理、资源库与登录**
- 项目和资源列表采用“搜索筛选 → 列表 → 详情”的结构，编辑表单按需打开。
- 登录页保留简洁单卡布局，补充字段标签、密码显隐、自动填充和可定位的错误提示。
- 统一加载、空数据、无权限、失败四种状态，避免不同页面使用各自的文案和样式。

## 五、建议的实施顺序

**第一阶段：修复操作与样式基础**
- 未保存保护、删除确认、滚动跟随策略、主题状态统一。
- 清理全局文本域高度、低对比度文字及触屏尺寸被覆盖的问题。
- 统一 `.btn` 与 `.button` 两套按钮体系。

**第二阶段：调整布局与视觉层级**
- 精简顶部和项目栏，划分主流程与辅助导航。
- 重做工作区高度分配与窄屏切换。
- 统一字体、间距、颜色、卡片、表单及状态样式。

**第三阶段：深化业务体验**
- 模型差异定位、验收失败筛选、资源详情面板。
- 拆分大型页面组件和样式文件，逐步接入现有公共组件，而不是再建一套并行体系。

**验收建议**：覆盖 1440px、1280px、1024px、390px 宽度及浅深主题，重点验证长项目名、长错误信息、流式输出、未保存切换和键盘操作。桌面不出现无意义的整页横向滚动，移动端主要动作可达，刷新后主题保持一致。

**最值得先做的是“操作保护 + 样式收敛 + 工作区高度重构”这三项；它们能为后续美化提供稳定基础。**
