# Tester 提案人工采信率评估输入

`script/eval-tester-proposal-reviews.py` 读取预先冻结的候选清单和人工复核标签，计算 M2 的用例采信率。工具离线运行，不读取数据库、不调用模型，也不生成审阅标签。

先确定项目、模型版本、Tester 报告范围和抽样方式。候选清单须覆盖该范围全部提案，或包含业务人员事先确定的代表性样本；不能在看到审阅结果后只留下已转用例、已通过或已采信的提案。清单、标签和抽样记录应一起保存。工具只能核查清单内覆盖率，不能证明清单本身完整或代表业务总体。

可用 Viewer 凭证从既有工作区与需求工作流 API 冻结当前报告：

```bash
API_TOKEN='<Viewer token>' python3 script/export-tester-proposal-inventory.py \
  <项目 ID> --output target/tester-inventory.jsonl
```

导出器两次读取并检查版本与业务摘要一致性，不按转换、Judge 建议或执行状态过滤提案；通过校验后以 `0600` 权限原子写入清单。它只采集当前仍保存在工作流中的报告，不能恢复被覆盖的历史报告或证明历史报告总体完整。要评估多个报告，应在各自生成后、业务审阅前及时冻结并留存清单，合并时保留全部四字段案例键。`--api-base` 可指定目标服务地址。

两个文件均为 UTF-8 JSONL，一行一个对象。允许空行和以 `#` 开头的注释；每个文件最多 100,000 条、32 MiB，每行最多 16 KiB。字段必须恰好符合下列格式，不接受业务输入、期望输出、提案正文或理由字段。

候选清单的每行包含：

| 字段 | 口径 |
|---|---|
| `projectId` | 正的有符号 64 位整数；不接受布尔值 |
| `versionId` | 冻结时关联的当前草稿版本，正的有符号 64 位整数；不推定历史报告原始归属 |
| `reportDigest` | 冻结 Tester 报告的 SHA-256，64 位小写十六进制；审阅批次开始前生成并固定 |
| `proposalId` | 报告内稳定标识，1–64 个 ASCII 字符，首字符为字母或数字，后续可含 `._:-` |

这四个字段共同标识一个案例。不同项目、版本或业务内容变化后的重生成报告中的同名提案分别统计。导出器的 `reportDigest` 绑定需求文本、原始需求、基线修订、需求卡、已确认回答、方案、报告 Schema 版本，以及按 ID 排序的全部提案业务字段（ID、类别、标题、理由、依据、输入字段、期望输出、待复核标记）。输入字段排序但不去重；忽略 Judge 结果、正式用例关联、执行状态和更新时间等处理状态。摘要通过键排序的紧凑 JSON、原始 Unicode 和 UTF-8 编码计算 SHA-256。评估工具仅校验摘要格式，不会重算或证明报告内容真实；内容完全相同的重生成也不会因此增加独立案例。

人工标签每行包含上述四个字段，再加入 `reviewer` 和 `label`。`reviewer` 使用稳定的脱敏人员标识，最多 255 个 UTF-8 字节，不含控制字符或首尾空格；不要填姓名、邮箱或其他个人信息。`label` 只能是：

| 标签 | 含义 |
|---|---|
| `accepted` | 人工判断该提案可用于补充业务测试覆盖 |
| `rejected` | 人工判断该提案不适用或存在错误 |
| `inconclusive` | 现有材料不足以独立判定 |

同一案例、同一 Reviewer 只能有一票。若需纠正录入错误，应保留纠错审计并重新生成只有最终票的导出文件。工具拒绝重复案例清单、重复票和不属于清单的标签。Judge 的 AI 输出与正式用例批准均不能直接替代这里的独立人工判断；采信提案也不等于批准发布。

工具不能验证标签是否由本人提交、人员是否独立或是否具备业务复核资格，这些事项由真实审阅采集流程核验。不要为补足样本量而生成标签或重复计入语义相同的案例。

调用方式：

```bash
python3 script/eval-tester-proposal-reviews.py \
  target/tester-inventory.jsonl target/tester-human-reviews.jsonl
```

报告按案例聚合，不按票数加权：忽略 `inconclusive` 弃权票后，`accepted` 多于 `rejected` 即为采信，反之为拒绝；票数相同为不确定。只有弃权票、正反平票、完全未审阅分别统计。单个 Reviewer 的多次重复票不会增加样本量。

`acceptance.rate` 的分母是可判定案例，默认目标为 70%。同时报告 `acceptedFractionOfAllCandidates`，即采信案例占全部冻结候选的比例，便于看到未审阅或不确定带来的影响。该比例不是对未审阅案例的负面业务判断。`coverage.reviewedRate` 表示至少有一票的覆盖率，`determinateRate` 表示能够形成正反结论的覆盖率。

默认至少需要 **100 个可判定案例**，且它们占冻结候选的比例达到 **90%**。不满足任一要求，状态为 `insufficient_samples`；满足后再按未四舍五入的采信率给出 `target_met` 或 `target_not_met`。`--minimum-cases`、`--minimum-coverage` 和 `--target-rate` 可在业务预先约定的验收方案中调整；开发时降低门槛得到的报告不能冒充默认业务验收通过。进程退出码 0 仅表示输入有效、报告生成成功，CI/验收须显式查看状态，不能把退出码当作质量通过。

Wilson 95% 区间针对已判定案例的采信比例，不校正案例之间的相关性、多 Reviewer 的共同偏差、样本选择偏差或报告重复生成造成的语义重复。报告中不输出案例标识、报告摘要、Reviewer 标识或业务正文；原始文件仍应按审阅材料权限保存。
