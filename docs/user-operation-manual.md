# 伏羲智能决策工作台操作手册

## 1. 手册说明

本手册面向使用伏羲智能决策工作台完成需求分析、DMN 建模、业务验收、版本发布和运行反馈的用户。

平台的新建模型标准闭环为：

```text
业务需求 -> 需求分析 -> 澄清确认 -> 规划方案 -> 方案确认
        -> 生成 DSL -> 编译 DMN -> 变更确认 -> 业务验收
        -> 自动验收 -> 发布服务 -> 运行反馈 -> 数据分析
```

已有模型的修改链路为：

```text
原始业务需求与当前 DSL -> 描述本次调整 -> 生成新的 DSL -> 编译 DMN
                      -> 变更确认 -> 业务验收 -> 自动验收 -> 发布
```

修改模型时不需要重新填写完整的新建需求，也不需要重复走新建模型的方案确认页面；系统会以原始需求和当前 DSL 作为受控修改上下文，仍然执行结构、依赖、DMN 和 FEEL 校验。

项目工作台按成员角色执行权限控制，角色在服务端实时生效：

| 角色 | 主要操作 |
| --- | --- |
| 所有者 | 管理成员、建模、查看运行数据；不能代替独立复核或发布审批 |
| 建模者 | 需求分析、方案、模型和版本草稿；生成、确认或驳回优化建议；回填实际业务结果 |
| 复核者 | 独立复核模型与批准业务案例 |
| 审批者 | 在复核和验收完成后发布版本 |
| 查看者 | 查看项目、版本、服务、运行记录、分析和审计，不能修改数据 |

> 重要：系统中的“确认”“批准”和“发布”动作均使用当前登录账号记录。正式环境应为每位操作者分配独立账号，不要共用账号。
>
> 同一账号可以拥有多个项目角色，但不能使用同一账号完成某版本的独立复核和发布审批；发布审批必须由未创建、未复核该版本的审批人执行。

## 2. 登录与账号

### 2.1 登录与退出

填写用户名、密码并完成 hCaptcha 人机验证，点击“登录”进入工作台。登录失败后需要重新完成 hCaptcha 验证。右上角“退出登录”会清除本地登录凭据并返回登录页。

登录凭据失效后，系统会清除无效凭据并跳转到登录页。重新登录后再继续操作；尚未提交到服务端的输入内容可能无法恢复。

首次部署时系统会创建超级管理员 `admin`。普通用户不能自行注册，由管理员在“用户管理”页面添加账号并设置系统角色。`admin` 的初始密码由服务端环境变量 `ADMIN_PASSWORD` 提供。

### 2.2 用户与系统角色（超级管理员）

超级管理员登录后，点击右上角“用户管理”，可以添加用户并选择“普通用户”或“超级管理员”角色，也可以修改已有用户的角色或密码。`admin` 的超级管理员角色不可被取消。

## 3. 工作台总览

顶部项目栏用于创建和切换项目、查看版本、打开知识库或模型库。项目工作区使用 Tab 切换以下视图：

| 视图 | 用途 | 可用条件 |
| --- | --- | --- |
| 需求与方案 | 编写需求、分析业务目标、回答澄清问题、规划并确认方案 | 始终可用；选择项目后可保存结果 |
| 决策建模 | 根据已确认方案生成 DSL/DMN，或基于当前 DSL 修改模型 | 已生成可用模型后可用 |
| 案例验收 | 维护业务案例、执行自动验收、发布版本 | 当前项目已有版本 |
| 决策服务 | 查看并调用已发布决策服务、回填实际结果 | 项目已有发布版本 |
| 运行分析 | 查看最近 30 天运行指标和确定性异常 | 项目已有发布版本 |
| 版本管理 | 查看版本链、变更审查、审计和创建回滚草稿 | 项目已有版本 |
| 项目协作 | 管理成员、角色和协作审计信息 | 已选择项目 |
| 资源中心 | 管理知识库和复用模型 | 始终可打开 |

Tab 支持键盘左右方向键、Home 和 End 切换。不可用的 Tab 会显示解锁条件；例如没有发布版本时不能进入“决策服务”和“运行分析”。

右上角还提供以下通用操作：

- “浅色/深色”：切换界面主题。
- “测试模型”：打开当前 DMN 的临时测试抽屉。
- “核验 DMN”：检查当前 DMN XML 结构和 FEEL 表达式。
- “退出登录”：结束当前会话。

## 4. 创建和切换项目

### 4.1 创建项目

1. 在顶部“新项目名称”中输入名称。
2. 点击“创建项目”。
3. 创建成功后，项目自动成为当前项目并进入“需求与方案”视图。

一个项目代表一条独立的决策生命周期，包含需求方案、模型版本、验收案例、发布服务、运行记录和审计事件。建议按业务边界创建项目，不要把无关业务规则放进同一项目。

### 4.2 切换项目

从“选择项目”下拉框选择目标项目。系统会恢复该项目的当前版本、模型产物、验收状态和发布信息。

切换前应先完成正在进行的变更确认。页面出现“变更确认”时，必须选择“放弃结果”或“确认并保存版本”，避免把未确认结果误认为已经保存。

## 5. 维护知识库

可直接使用的术语、字段目录、制度政策和建模关联示例见 [知识库与建模关联示例](knowledge-base-examples.md)。

进入“资源”并选择“知识库”。知识源支持三种类型：

- 企业术语：统一业务概念、枚举值、定义和口径。
- 字段目录：描述字段名称、类型、单位、来源和约束。
- 制度政策：记录政策条款、规则依据和有效时间。

### 5.1 新建知识源

1. 点击知识目录右侧“新建”。
2. 使用“知识源类型”选择器选择企业术语、字段目录或制度政策。
3. 填写名称和知识内容，这两个字段必填。
4. 按需填写版本、说明、生效日期、失效日期和来源地址。生效日期和失效日期使用日期选择器填写。
5. 点击“创建知识源”。

日期用于判断知识当前是否有效。失效日期不应早于生效日期。来源地址建议填写可追溯的制度页面、文档地址或数据字典地址。

### 5.2 编辑、搜索和归档

- 使用顶部搜索框按名称、说明或内容检索。
- 使用“全部、已绑定、术语、字段、制度”筛选目录。
- 点击知识项的“编辑”，修改后点击“保存修改”。
- 点击“归档”停用知识。归档知识不能再绑定到项目。

### 5.3 绑定项目

1. 先在顶部选择目标项目。
2. 找到知识源。
3. 勾选“绑定当前项目”。

只有同时满足以下条件的知识才会进入该项目的智能建模上下文：

- 属于当前用户；
- 已绑定当前项目；
- 状态为启用；
- 当前日期位于生效和失效日期范围内。

建模后，版本会固化知识引用快照。“建模”页顶部的“当前版本知识依据”可以查看引用。后续编辑、归档或失效知识源不会改写历史版本。

## 6. 从自然语言创建模型

### 6.1 编写需求

进入“需求与方案”视图，在需求输入框中描述：

- 业务目标；
- 输入字段、类型、单位和必填规则；
- 输出字段及含义；
- 阈值、优先级、兜底规则；
- 决策之间的依赖；
- 需要的业务知识模型或决策服务；
- 关键验收场景。

示例：

```text
创建贷款资格决策。输入 age、income、creditScore，分别为 number。
年龄小于 18 岁拒绝；信用分小于 600 拒绝；收入低于 5000 元转人工；
其余批准。输出 Eligibility，类型为 string，并提供默认兜底规则。
```

### 6.2 分析需求

点击“开始分析需求”。系统会提取业务目标、输入、输出、约束和歧义，并显示面向业务人员的需求分析结果，包括业务目标、关键业务规则、需要提供的信息、最终判断结果、业务术语和风险提示。

分析开始后页面会自动滚动到页面底部，展示“正在分析需求”进度卡片。分析完成后会自动定位到“需要你确认的问题”区域，避免用户错过待处理事项。

如果出现澄清问题，应逐项填写。标记为“需要回答”的问题会使用高亮样式，必须回答后才能生成或重新规划方案；“可选补充”用于补充业务背景。对未明确的阈值、空值策略、优先级和输出含义，不建议直接使用含糊回答。

如果需求已经发生变化，点击“重新分析”。系统会保留当前页面中的原始需求，并在分析完成后重新生成摘要和澄清问题。

### 6.3 生成并确认方案

1. 在“需求与方案”视图点击“生成决策方案”。
2. 检查决策清单、表达式类型、依赖、业务知识模型、决策服务、默认策略和验收标准。
3. 发现问题时修改原始需求并点击“重新分析”。
4. 确认方案正确后点击“确认方案”。

确认后页面显示“方案已确认，可生成模型”。方案确认是生成可执行模型的前置条件。

### 6.4 生成 DSL 与 DMN

方案确认后，切换到“决策建模”视图，点击“使用方案生成模型”。系统会：

1. 调用智能体生成结构化 DSL；
2. 校验名称、类型、引用、表列和依赖；
3. 编译 DMN XML；
4. 解析并编译 FEEL 表达式；
5. 对可修复错误自动反馈并重试；
6. 返回通过结构和语法核验的模型。

“执行过程”显示各阶段状态；“模型产物”可查看 DSL YAML、DMN XML、结构、图形和源码等视图。YAML 结构视图支持层级折叠、搜索和预览，YAML 与 DMN/XML 源码支持语法高亮。结构和语法通过不代表业务规则必然正确，仍需进行变更确认与验收。

快捷键：在需求输入框使用 `Ctrl + Enter` 或 `Cmd + Enter`，系统会根据当前阶段执行分析需求、生成方案、确认方案或生成模型。

## 7. 修改当前模型

项目已有模型时，进入“决策建模”视图并切换为“修改当前决策模型”模式。页面会同时展示原始业务需求和只读的“当前版本 DSL · 受控补丁基线”。

只描述需要修改的内容，例如：

```text
将信用分拒绝阈值从 600 调整为 620，其他决策、依赖和默认规则保持不变。
```

点击“分析需求变更”后，系统基于原始需求和当前 DSL 生成新的 DSL，再编译 DMN，并执行完整的结构、依赖和 FEEL 校验。该链路不要求重复填写完整需求或重新走新建模型的方案确认。不要在一次请求中混合多个互不相关的大范围调整；拆分修改更容易审查和回退。

## 8. 变更审查和保存草稿

模型生成或修改完成后不会立即保存。页面会显示“变更确认”，其中包括：

- 总体风险等级；
- 风险发现和涉及元素；
- 新增、修改或删除的元素；
- 元素类型；
- 变更前后值；
- 变更原因。

操作方式：

1. 逐项检查差异和风险提示。
2. 如结果不正确，点击“放弃结果”。
3. 如结果正确，勾选确认声明。
4. 点击“确认并保存版本”。

每次确认都会创建新的草稿版本，不覆盖历史版本。保存完成后进入“验收”视图继续处理。

## 9. 检查模型产物

### 9.1 DSL YAML

重点检查输入数据、数据类型、决策、表达式类型、决策表规则、依赖、业务知识模型和决策服务。YAML 是智能生成和受控修改的主要结构化产物。

优先使用“结构”视图按层级检查模型，再使用源码视图核对具体值。结构视图支持搜索、展开和折叠；长值会在局部区域滚动或换行，不需要拖动整个页面。

### 9.2 DMN XML

DMN XML 是实际编译和执行的模型。源码视图提供 XML 语法高亮，便于识别元素、属性、表达式和引用。通常只读检查；如果 DSL 与 XML 表达的结构不一致，应放弃当前生成结果并重新生成，而不是绕过流程直接修改历史版本。

### 9.3 核验 DMN

点击顶部“核验 DMN”。系统检查 XML 结构、引用、数据类型和 FEEL 表达式。核验失败时，根据页面显示的具体元素和错误修正需求或修改指令。

## 10. 临时测试当前模型

点击顶部“测试模型”打开“核验与测试”抽屉：

1. 检查只读的 DMN XML。
2. 点击“核验模型”，系统分析输入并自动生成 JSON 模板。
3. 在“JSON 输入”中填写测试值。
4. 点击“执行测试”。
5. 检查决策输出、诊断信息和确定性执行轨迹。

示例输入：

```json
{
  "age": 35,
  "income": 12000,
  "creditScore": 720
}
```

JSON 键应使用页面分析出的执行键。若模型定义了 `variable`，执行键可能与 `inputData` 的显示名称不同。

临时测试用于快速核对当前产物，不替代持久化业务验收案例和发布门禁。

## 11. 业务验收

进入“验收”视图。业务验收测试套件包含人工案例和系统生成的候选案例。

### 11.1 添加人工案例

填写：

- 案例名称：清楚描述业务场景；
- 输入 JSON：完整的模型输入对象；
- 期望输出 JSON：需要断言的决策输出。

期望输出可以只包含需要验收的决策子集，例如：

```json
{
  "Eligibility": "approved"
}
```

点击“添加案例”。输入和期望输出必须是有效的 JSON 对象。

### 11.2 生成候选案例

点击“生成候选案例”。系统会根据可反解的数值比较、区间、字符串、布尔常量、枚举和普通 OR 条件生成候选输入，并以模型真实执行结果作为候选期望输出。

候选案例只用于提高规则覆盖效率：

- 不会自动批准；
- 必须由业务人员核对；
- 复杂 FEEL、依赖决策输入和不可达规则可能被跳过；
- 生成摘要会说明生成和跳过情况。

### 11.3 运行和核对案例

1. 点击“运行全部”。
2. 检查每个案例的输入、期望和实际结果。
3. 对不一致或错误案例，展开“查看执行轨迹与解释”。
4. 修正模型或案例后重新运行。

案例状态包括待运行、通过、不一致和错误。执行轨迹来自真实运行，不调用大模型推测业务原因。

### 11.4 批准案例

只有状态为“通过”的案例才能点击“批准”。所有用于发布的业务案例都应由有权验收的人员逐项核对和批准。

修改模型后应重新运行和批准相关案例。已发布或已退役版本中的案例不可修改、删除、运行或重新批准。

## 12. 自动验收与发布门禁

业务案例处理后，执行“自动验收”。系统会检查：

- 基础样本；
- 缺失输入；
- 错误输入类型；
- 可识别数值阈值的下界、等值和上界；
- `UNIQUE` 规则重叠；
- `ANY` 规则输出冲突；
- `FIRST` 不可达规则；
- 规则覆盖缺口；
- 业务案例是否全部通过并批准。

页面会显示门禁、风险发现和自动案例详情。阈值边界失败时可点击“查看失败边界案例”展开具体输入与执行错误；警告需要人工评估，阻断级失败必须修正后重新验收。

发布需要同时满足：

- 技术门禁通过；
- 至少存在一个业务验收案例；
- 必填业务案例全部运行通过；
- 通过案例均已批准；
- 发布负责人勾选发布确认声明。

全部满足后点击“确认发布”。发布版本不可变；发布新版本时，上一个发布版本自动转为 `retired`。

## 13. 调用已发布服务

进入“服务”视图。页面展示当前发布版本中的每个 DMN `decisionService`：

- 服务名称和版本；
- 调用地址；
- 输入字段和类型；
- 输出字段和类型。

页面内调用步骤：

1. 选择决策服务。
2. 填写业务关联号，例如订单号、申请号或案件号。
3. 按输入契约填写“调用输入 JSON”。
4. 点击“调用服务”。
5. 查看输出、耗时和执行轨迹。

服务只接受契约声明的输入字段，缺少必填字段或包含额外字段都会被拒绝。响应顶层只返回服务声明的输出决策。

外部系统调用时使用页面展示的地址：

```text
POST /api/public/projects/{project_id}/decision-services/execute
X-Decision-Key: dmn_live_<secret>
Content-Type: application/json

{
  "serviceId": "<service_id>",
  "businessReference": "ORDER-2026-0001",
  "inputs": { "Amount": 1200 }
}
```

服务页的“对外调用凭证”区域可以生成和撤销凭证。凭证按项目和服务绑定，完整密钥只在生成成功时显示一次，数据库仅保存 Argon2 哈希。凭证支持过期时间，每个项目最多保留 50 个有效凭证；项目成员失去查看权限后，其创建的凭证也不能继续执行。生产环境还应在网关侧启用 HTTPS、按 IP/凭证限流，并限制允许的来源。

外部调用和页面内调用共用 `decision_runs` 运行记录，包含版本、输入、输出、耗时、状态和执行轨迹。执行完成后进入“分析”视图即可在运行分析与确定性异常发现中查看，按当前发布版本和最近 30 个 UTC 自然日聚合。

## 14. 回填实际业务结果

服务页“运行反馈与实际结果”展示最近运行记录。成功运行可以回填：

- 业务关联号；
- 结果发生时间；
- 实际业务结果 JSON；
- 结果判定：符合决策、存在偏差、无法判断；
- 反馈说明。

点击“回填实际结果”或“修改实际结果”，完成后点击“保存实际结果”。业务关联号必填。

反馈只作为分析数据，不会自动修改模型、创建版本或改变发布状态。发现偏差后，应回到正常的增量修改、变更确认、验收和发布流程。

## 15. 查看运行分析

进入“分析”视图。系统按当前发布版本隔离统计最近 30 个 UTC 自然日的数据，不混合历史版本。

主要指标包括：

- 运行总量和失败率；
- 反馈覆盖率和偏差率；
- 平均耗时和 P95 耗时；
- 决策表规则覆盖率；
- 默认输出和无匹配次数；
- 决策结果分布；
- 每日运行、失败、反馈、偏差和耗时趋势。

“确定性异常”使用固定样本门槛和阈值识别高失败率、高偏差率、低反馈覆盖、低规则覆盖、频繁兜底、长尾耗时及最近趋势恶化。分析过程不调用大模型，也不会自动修改模型。

### 15.1 处理优化建议

建模者在“分析”视图点击“生成优化建议”。每条建议都会保存来源发布版本、异常证据和分析快照。可选择：

- “确认并创建草稿”：仅从建议的当前发布版本复制出新草稿与业务案例，保留未复核状态；随后在“建模”中完成实际修改，并按正常核验、验收、独立复核和发布流程推进。
- “驳回”：保留驳回人与时间的审计记录，不修改任何版本。

如果发布版本或当前草稿已经变化，系统会拒绝确认旧建议，必须重新生成。优化建议、确认和驳回均不会自动修改或发布线上模型。

## 16. 版本历史、审计和回滚

进入“版本”视图查看：

- 版本号、状态、创建人和时间；
- 当前版本；
- 回滚来源和原因；
- 项目创建、版本创建、验收、批准、发布、退役、回滚、服务调用和反馈等审计事件。

顶部“版本变更”下拉框可查看某个已保存版本的变更摘要、风险和逐项差异。

### 16.1 创建回滚草稿

1. 从“版本变更”选择一个非当前的已发布或已退役版本。
2. 检查该版本的历史变更。
3. 填写回滚原因。
4. 勾选回滚确认声明。
5. 点击“创建回滚草稿”。

回滚不会覆盖历史版本，也不会立即切换线上服务。系统会复制目标版本的模型产物和业务案例，创建新的草稿版本，并清空案例执行与批准状态。新草稿必须重新完成业务验收、自动验收和发布。

## 17. 使用模型库

进入“资源”并选择“模型库”。模型来源包括：

- 行业模板：平台内置模板；
- 我的模板：当前用户保存的模板快照；
- 发布历史：当前用户已发布或已退役的历史模型。

可按来源筛选，也可按名称、行业和说明搜索。

### 17.1 复用模型

1. 选择模型。
2. 查看来源、行业、风险等级、案例数量和说明。
3. 填写新项目名称。
4. 勾选“确认创建独立草稿，并重新执行测试、批准和发布门禁”。
5. 点击“创建复用项目”。

复用会创建独立项目和 `v1` 草稿。需求方案、DSL、DMN 和业务案例可以复制，但案例执行、人工批准、自动验收和发布状态全部重置；后续修改不会影响来源模型。

### 17.2 保存和删除个人模板

选择“发布历史”模型后，可填写模板名称和行业标签，点击“保存快照”。选择“我的模板”中的模板后，可点击“删除个人模板”。删除模板不会删除来源项目和历史版本。

## 18. 主题、窗口和移动端

- JSON、YAML、XML 和执行结果区域使用代码编辑器配色；普通表单使用页面表单配色。
- 浅色和深色主题都提供独立的文字、占位符、光标和焦点对比度。
- 工作台使用统一的自定义选择器和日期选择器；键盘用户可以使用 Tab、方向键、Enter 和 Escape 完成选择或关闭菜单。
- 较窄窗口下，项目栏、资源库、验收案例和分析区域会改为纵向布局。
- 长 YAML、表达式、服务地址和 JSON 会自动换行或提供区域滚动，不应依赖浏览器整体横向滚动。

在移动设备上建议一次完成一个短操作；模型审查、复杂 JSON 编辑和版本差异核对更适合桌面浏览器。

## 19. 常见问题

### 19.1 页面自动返回登录页

登录令牌已失效或被服务端拒绝。重新登录并重新完成 hCaptcha 即可。若频繁发生，请管理员检查服务端 `JWT_SECRET` 是否在重启时变化，以及客户端和服务端时间是否准确。

如果登录接口返回 `401 Unauthorized`，先检查以下项目：

- hCaptcha 是否已经完成，登录页是否显示验证成功状态；
- 当前部署是否能从浏览器访问 hCaptcha 脚本，并能从服务端访问 hCaptcha 校验接口；
- hCaptcha 的站点密钥和服务端密钥是否属于同一站点配置；
- 是否重复使用了过期或已消费的 token。刷新验证后再登录。

登录错误信息会优先展示服务端返回的具体原因。若仍无法登录，联系管理员检查服务端日志、频率限制和 hCaptcha 配置，不要反复提交相同 token。

### 19.2 登录或接口返回 500

页面会展示后端返回的可用错误信息。联系管理员检查服务日志、数据库连接和数据库迁移是否完整。开发环境可设置 `APP_ENV=development` 返回更具体的数据库错误；生产环境不应向浏览器泄露数据库内部信息。

### 19.3 提示 `permission denied for table users`

这是 PostgreSQL 应用账号缺少表或序列权限，需要数据库管理员执行授权脚本。普通业务用户无法在页面内修复。

### 19.4 页面资源 `/pkg/fuxi-dmn.js` 返回 404

前端静态资源尚未构建，或服务启动时的站点目录不正确。管理员应执行生产构建脚本，并确认 `target/site/pkg/` 已生成后再启动后端。

### 19.5 模型提示 `thinking mode does not support this tool_choice`

当前模型服务不接受推理模式下的强制工具选择。系统对 `deepseek-v4` 和 `deepseek-reasoner` 会自动省略函数级 `tool_choice`，并让服务端从唯一工具中自动选择；修改服务配置后需重启后端。其他模型应按服务商文档关闭 thinking 模式，业务用户不需要修改需求内容来规避此错误。

### 19.6 “确认发布”按钮不可用

依次检查：

- 是否已执行自动验收；
- 技术门禁是否通过；
- 是否至少有一个业务案例；
- 所有必填案例是否通过；
- 所有通过案例是否已批准；
- 是否勾选发布确认声明。

### 19.7 服务或分析页签不可用

当前项目还没有发布版本。先在“验收”视图完成验收并发布。服务页优先展示模型中显式定义的 `decisionService`；如果模型只包含普通决策，系统会按终端决策生成默认可调用服务。

### 19.8 生成结果没有保存

生成成功后仍需在“变更确认”中勾选确认并点击“确认并保存版本”。仅看到 DSL 或 DMN 预览不代表已经创建版本。

### 19.9 候选案例已通过但仍不能发布

通过不等于批准。候选案例必须由业务人员核对并逐项点击“批准”，同时还要满足自动验收门禁。

### 19.10 点击“分析需求”后看不到进度

分析开始后页面会自动滚动到工作流底部，并显示“正在分析需求”进度卡片。若当前浏览器阻止了滚动或页面仍停留在旧位置，可手动滚动到“需求与方案”视图底部；分析完成后页面会再次定位到“需要你确认的问题”。

### 19.11 不知道先回答哪些澄清问题

优先处理带有“需要回答”标记的问题。这些问题会使用高亮边框和徽章显示，并且未回答时不能生成决策方案。带有“可选补充”标记的问题不会阻止流程，但建议在涉及例外、阈值、空值或业务口径时补充说明。

## 20. 操作与治理规则

1. 不在需求、知识内容、测试 JSON 或反馈说明中录入密钥、密码和不必要的敏感个人信息。
2. 模型生成和语法核验不能代替业务审核。
3. 高风险变更应由非修改人复核。
4. 每个发布版本至少保留覆盖关键正常、拒绝、边界和兜底场景的业务案例。
5. 候选案例不能直接视为业务真值。
6. 知识变更后，涉及该知识的新版本应重新建模或修改并重新验收。
7. 不直接修改已发布或已退役版本；所有调整创建新草稿。
8. 回滚也必须重新验收和发布，不能绕过门禁。
9. 实际结果反馈和运行分析只提供证据，不自动驱动线上规则变化。
10. 发布、回滚和偏差处理应填写可追溯的业务原因，并结合审计记录复核。

## 21. 推荐日常检查清单

发布前：

- 需求摘要和方案已由业务人员确认；
- 字段类型、单位、空值和默认策略明确；
- 决策依赖、命中策略和服务输入输出正确；
- 版本差异和风险已逐项检查；
- 关键业务案例、边界案例和兜底案例已通过并批准；
- 自动验收门禁通过；
- 发布负责人完成最终确认。

发布后：

- 使用真实但脱敏的样本完成一次服务调用；
- 检查业务关联号、输出和执行轨迹；
- 定期回填实际结果；
- 关注失败率、偏差率、规则覆盖和 P95 耗时；
- 发现问题时创建新草稿修正，不直接改变历史版本或线上数据。
