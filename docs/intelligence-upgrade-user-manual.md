# 智能升级功能操作说明

本文补充[工作台操作手册](user-operation-manual.md)，对应当前工作区的 Tester 辅助复核、决策解释和人工审阅功能。部署时需按 [README](../README.md) 完成数据库迁移并同时升级后端和前端。

## 测试工程提案与 AI 建议复核

1. 建模者在“需求与方案”中完成规划，查看“测试工程提案”。
2. 展开某条提案的“填写输入与期望输出”，根据业务事实填写 JSON；期望输出至少包含一个决策断言。
3. 可点击“AI 建议复核”，查看两次采样的理由。两票一致时显示未发现明显问题或可疑；不一致、证据不足时显示无法形成结论。
4. 根据业务核对结果调整输入和期望输出。编辑后原 AI 结论过期；再次复核会绑定当前业务上下文和提示词版本。
5. 点击“保存为待执行用例”，再运行已转换用例。独立复核者仍需按原业务验收流程逐项批准，通过后再完成人工发布。

两次采样复用同一个 Judge Agent，不代表两个独立供应商的共识。AI 结论仅供参考；采样一致不能代替业务真值、人工采信或发布批准。

## 决策运行解释

在服务运行历史中展开成功运行。建模者点击“生成/查看解释”可启动后台生成；其他有查看权限的成员点击“查看解释”读取已有结果。页面展示决策摘要和各决策步骤说明。

失败运行不能生成业务解释。生成失败后可由建模者重新发起；处理中页面会轮询，长任务超过本次页面等待时会提示稍后重新查看。解释生成独立于决策执行，运行输出和原始轨迹仍是核对依据。

取消或失联回收的任务会停止本地等待并关闭相应缓存；晚到结果不会覆盖终态或后续重试。供应商是否继续计算或计费取决于其服务行为。

## 复核者记录可读性结论

1. 使用项目复核者账号打开成功解释并阅读当前文本。
2. 主动选择“清晰可读”“需要改进”或“无法判断”，点击“记录审阅”。
3. 提交前不显示该版本的既有人工标签；提交后可查看记录。
4. 若提示解释已更新，重新点击“查看解释”，阅读新文本后再判断。

每位复核者对同一解释的每个生成版本只能投一票。解释重生成后，旧标签不会自动成为新文本的结论。无法证明文本版本的升级前标签仍予保留，但不进入当前可读性统计或导出。

可读性判断不等于证明业务解释正确，也不批准模型或改变决策输出。管理页面的当前缓存统计、模型调用耗时和人工质量标签需结合样本量分别判断。

## 组织业务验收

Tester 采信率评估先冻结候选清单，再独立收集人工标签；不要只挑选已转换或已批准的提案。导出与评估命令、输入字段和默认门槛见 [Tester 采信评估说明](tester-proposal-review-format.md)。工具不会自动填写人工标签。

解释可读性标签可以使用 README 中的 `export-decision-explanation-reviews.py` 导出，再用 `eval-decision-explanation-reviews.py` 评估。导出文件包含解释版本；旧格式文件须重新导出。对同一解释反复重生成不会增加独立案例数。

编排验收可以使用[编排运行观测工具](agent-orchestration-evaluation.md)区分尝试、重试家族和预算树；预算未知不能按零处理。RAG 维护者可先用[检索评估工具](rag-evaluation.md)的 `--validate-only` 检查标注集，随后在获准环境运行在线诊断；串行调试延迟不能代替稳定负载验收。

归因质量统计应同时导出已审标签和全部案例清单，保留未审阅、证据不足样本，再按[归因评估说明](deviation-attribution-evaluation.md)检查覆盖率及准确率。100 例 / 75% 只提供数值比较；现有可改判项目标签不能证明独立盲审过程。

真实脱敏样本、人工独立性、抽样代表性和目标环境的响应时间仍需单独验收。固定契约测试通过不表示 70% 采信率、85% 可读性或 P95 目标已经达成。
